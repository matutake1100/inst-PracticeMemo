## コマンド一覧
- ### git init
	カレントディレクトリをGitリポジトリーとして管理されるようにするコマンド（初期化）
- ### git add ファイルパス
	　作業ディレクトリーにある指定されたファイルをステージングエリアに記録する。Gitの管理下（追跡済み）となる
- ### git commit -m 'コミットメッセージ'
	git addでステージングエリアに上がっているものを変更として登録する。その際にどこを変更したか、何をしたかをコミットメッセージで簡潔に書いておく
- ### git push
	ローカルリポジトリのコミット履歴をリモートリポジトリへ送信し、リモートリポジトリのコミット履歴を更新する
- ### git rm ファイルパス
	作業ディレクトリからファイルが削除されてその変更がステージングエリアに反映される。
- ### git rm --cached
	ファイルをGitの管理対象外（未追跡）へ戻す操作が実行される。ファイル自体は削除されない
- ### git mv 移動元のファイル 移動先のパス
	作業ディレクトリ内の「移動元」に指定したファイルが、「移動先」のパスへ移動する。
	また、ファイルの名前の変更もこれで行える。
- ### git restore
	ファイルパスを指定してステージングエリアに記録されたファイルや作業ディレクトリーにあるファイルの状態を、指定の状態に戻す。
- ### git restore -s ソース ファイルパス
	指定ファイルを指定のソースの状態に戻す。
- ### git restore --staged ファイルパス
	ステージングエリアの下書きをHEADの状態（直前のコミット）に戻す。addを取り消すコマンド
- ### git commit --amend　-m 'コミットメッセージ'
	間違った内容をコミットした際に新しいコミットで上書きできる。（コミットメッセージを間違えた場合やファイルの間違いがあった場合）
	※pushしていない場合に限る
- ### git revert コミットのID
	指定したIDのコミットで行った変更とは逆の操作を実行して新たなコミットとして記録する
	過去の変更点の中に問題を生じさせる操作があった場合にそのコミットの変更点をそのままもとに戻せる。うまくいかなかった場合はコンクリクトという状態になる。
- ### git reset コミットのID
	基本的には行われない。例外的なもの。
	push前のモノで上書きせずに単に取り消したい場合に使う。指定されたコミットより後のコミット履歴がすべて消える。（HEAD^を指定するとHEADが
	履歴から消える）
- ### git diff
	作業ディレクトリ内のまだステージング（add）されていない変更点を表示する
